# Engineering
- Correctness first, then maintainability six months out.
- Delete weightless code. Refuse needless abstractions. Prefer the boring, proven design.
- Start with the smallest end-to-end working version that meets the agreed scope, then add complexity only when needed.
- Before writing custom code or adding a dependency, confirm the existing dependencies cannot already do it; read their docs and type definitions instead of assuming a capability is missing.
- Design for long-term evolution; do not ship a stopgap that is expected to be replaced later.
- Respect the user's reports and observations as evidence. Reproduce or inspect only when it helps locate a cause or verify a fix.
- Unexpected changes in the repository are the user's work. Adapt to them instead of undoing them.
